# Book LLM Wiki 운영 규칙 (Schema) v1.0

> 이 볼트는 카파시(Karpathy)의 LLM Wiki 방식으로 운영하는 **eBook 기반 지식 데이터베이스(wiki)** 임
> 사람: 책 고르기 · NotebookLM에 추가 · 질문 · 검토 / Claude: 추출 · 작성 · 연결 · 정리 · 기록
> 규칙을 바꿀 때는 사용자와 합의 후 버전을 올리고 log.md에 `스키마` 기록

## 0. 목적과 범위
- 목적: 보유 eBook의 내용을 구조화해 **분야를 가리지 않고 찾고·연결하고·재사용할 수 있는 지식 데이터베이스**를 만드는 것
- 범위: 분야 제한 없음. 서고 구성이 한 분야에 치우쳐 있어도 경영·마케팅·AI·인문·과학·종교 등 모든 분야를 같은 규칙으로 다룸
- 특정 분야에 맞춘 전용 폴더·인용 체계·관점을 두지 않음. 분야별 특성은 태그와 개념 페이지로 표현함
- 가치의 핵심은 **분야를 넘나드는 연결** (예: 리더십 개념이 종교 도서와 경영 도서에서 어떻게 다른지)

## 1. 위치와 자원

| NotebookLM | Google 계정. 브라우저 작업은 **Aside CLI(`aside exec`)** 사용 |
| 프롬프트 | `99_admin/prompts/P01_책별추출.md`, `P02_묶음비교.md` |
| 템플릿 | `99_admin/templates/T_책·T_개념·T_엔티티·T_종합.md` |

| 사람용 설명서 | `99_admin/guide/워크플로우설명서.md` — 이 규칙의 명령어·절차를 바꾸면 설명서도 새 버전으로 함께 갱신 |

## 2. 폴더 규칙

| 폴더 | 내용 | 쓰기 권한 |
|---|---|---|
| `00_HOME.md`, `00_dashboard/*.base`, `00_dashboard/대시보드.md` | 홈 화면, Bases DB 보기, Dataview 대시보드 (frontmatter 기반 자동 집계) | 합의 후 수정 |
| `01_inbox/` | 수동으로 붙여넣은 추출본 (Aside 실패 시 대체 경로) | 사람 |
| `10_raw/<노트북명>/` | NotebookLM 추출본 원형 보관 | Claude가 **저장만**, 이후 수정 금지 |
| `20_books/` | 책 페이지 (위키화한 책만) | Claude |
| `30_concepts/` | 개념·주제 페이지 | Claude |
| `40_entities/` | 인물·저자·전통/학파·기관·도구·작품 | Claude |
| `50_synthesis/` | 묶음 종합, 질문 답변 저장본 | Claude |
| `60_outputs/` | 사용자가 요청한 산출물 초안 | Claude (요청 시) |
| `80_journal/` | 사용자의 메모·생각·적용 기록 | **사람 전용 — Claude는 읽기만, 수정·요약·이동·삭제 금지** |
| `90_assets/` | 이미지 | Claude |
| `99_admin/` | 설명서·프롬프트·템플릿 | 합의 후 수정 |

- **미리 만들지 않음**: 책·개념·인물 페이지는 위키화 과정에서 실제로 필요할 때만 생성. 빈 페이지를 대량으로 만들지 않음
- 원본 PDF(Drive)는 절대 수정·이동·삭제하지 않음
- **frontmatter는 DB 필드임**: 템플릿의 속성 이름(type, author, category, notebook, status, ingested, sources, kind, confidence, updated, question, created)을 바꾸거나 빼지 않음. `sources`는 반드시 목록(`- "[[책]]"`) 형식. 날짜는 `YYYY.MM.DD` 텍스트
- 속성 타입 정의: `.obsidian/types.json` / 템플릿 폴더 설정: `.obsidian/templates.json`

## 3. 명령어 (사용자가 Claude Code에 말하는 문장)

| 명령 | 언제 | Claude가 하는 일 |
|---|---|---|
| `위키화 <노트북명>` | NotebookLM 노트북에 책을 추가한 뒤 | 4장 절차 전체 실행 |
| `위키화 inbox` | Aside가 안 될 때, 추출본을 01_inbox에 직접 붙여넣은 뒤 | 4장 ④부터 실행 |
| `신규 확인` | 원본 서고 폴더에 새 책을 넣은 뒤 | 5장 절차 실행 |
| `질문: <내용>` | 언제든 | 6장 절차 실행 |
| `점검` | 월 1회 권장 | 7장 절차 실행 |
| `현황` | 언제든 | 시트 H열 집계 + index 현황 + 최근 log 5건 보고 |

## 4. 위키화 절차 (`위키화 <노트북명>`)

### 사람이 먼저 하는 일
1. 원본 서고 폴더(또는 도서목록 시트)에서 책 고르기
2. NotebookLM에서 노트북을 만들거나 기존 노트북을 열고, 고른 PDF를 소스로 추가 (200MB 초과 파일은 분할)
3. Claude Code에 `위키화 <노트북명>` 입력

### Claude가 이어서 하는 일
① **준비**: 이 문서, `index.md`, `log.md` 최근 기록을 읽음

② **소스 확인** (Aside)
```bash
aside exec "NotebookLM(https://notebooklm.google.com)에서 '<노트북명>' 노트북을 열고 소스 목록의 제목을 모두 알려줘. 아무것도 수정하지 말고, 결과는 <<<BEGIN>>>과 <<<END>>> 사이에 한 줄에 하나씩 적어줘."
```

③ **시트 대조**: Drive 도구로 시트를 CSV로 내려받아 소스 제목과 D열(도서명)·파일명을 맞춤
- H열이 `위키반영`·`검토완료`인 책은 건너뜀 (이미 위키에 있음)
- 시트에 없는 책 → 5장 신규 등록 대상으로 따로 보고
- 대조 결과(새로 위키화할 책 목록)를 사용자에게 보여주고, **불일치가 있을 때만** 질문하고 없으면 그대로 진행

④ **책별 추출** (책 1권씩, Aside)
```bash
aside exec "NotebookLM '<노트북명>' 노트북에서 소스 '<소스 제목>' 하나만 선택하고 나머지 소스는 선택 해제한 뒤, 채팅창에 아래 프롬프트를 그대로 입력해줘. 답변이 끝나면 답변 전문을 줄임 없이 <<<BEGIN>>>과 <<<END>>> 사이에 그대로 출력해줘. 노트북 설정이나 소스는 바꾸지 마. 프롬프트: <P01 코드블록 내용>"
```
- 출력의 BEGIN~END 사이만 잘라 `10_raw/<노트북폴더>/<도서명>_P01.md`로 저장 (묶음 비교는 `_P02_YYYYMMDD.md`)
  - `<노트북폴더>`: 노트북명에서 `[` `]` 제거, `/`는 `_`로 바꾸고 앞뒤 공백 정리 (예: `[e-Book / 인문] 사피엔스_유발 하라리` → `e-Book_인문 사피엔스_유발 하라리`)
  - 파일명 끝 `_P01`은 책 페이지(`20_books/<도서명>.md`)와 이름이 겹쳐 링크가 헷갈리는 것을 막기 위함
- 파일 맨 위에 다음을 붙임
  ```
  ---
  source: <소스 제목>
  notebook: <노트북명>
  extracted: YYYY.MM.DD
  method: aside | 수동
  ---
  ```
- 답변이 잘렸거나 비어 있으면 1회 재시도, 그래도 안 되면 사용자에게 수동 붙여넣기(`01_inbox`) 요청
- 0번 "인식 품질"이 `읽기 어려움`이면 그 책은 위키화하지 않고 시트 H열 `보류`, 사용자에게 보고

⑤ **묶음 비교** (이번 위키화 책이 2권 이상일 때, Aside로 해당 책만 선택하고 P02 실행) → `10_raw/<노트북폴더>/<노트북폴더>_P02_YYYYMMDD.md`

⑥ **Ingest** (책 1권씩 순서대로)
1. 추출본 5줄 요약과 인식 품질을 사용자에게 먼저 보여줌 (강조할 점이 있으면 반영)
2. `20_books/<도서명>-<저자>.md` 생성 (T_책 템플릿, 시트의 대분류·링크 반영, 시트 저자 오류는 바로잡아 기록)
3. 개념·인물 등 페이지 생성 또는 갱신 (같은 대상은 반드시 1개 페이지로 통합, aliases 활용)
   - 기존 내용과 다르면 구분 표기: `🔀 관점 차이`(해석·전통이 다름, 양쪽 출처 병기) / `⚠️ 사실 충돌`(사실관계가 다름, 원문 대조 대상)
   - 학파·사상·종교·이론 간 차이는 판정하지 않고 각 입장을 공정하게 기록
   - 같은 개념이 다른 분야 책에 나오면 하나의 개념 페이지에 분야별 관점으로 함께 정리 (분야 간 연결 우선)
4. 책 1권이 보통 개념·인물 5~15개 페이지에 영향을 줌. 의미 없는 페이지를 억지로 만들지 않음

⑦ **종합**: 2권 이상이면 `50_synthesis/<노트북명>_묶음종합.md` 생성 또는 갱신 (P02 결과 + 위키 페이지 근거)

⑧ **마무리**
- `index.md` 갱신 (현황 숫자, 노트북·책·개념·인물·종합 목록)
- 시트 갱신 (Aside): 해당 행 H열 `위키반영`, I열 `<노트북명>`
  ```bash
  aside exec "Google Sheet https://docs.google.com/spreadsheets/d/<sheet_id>/edit 에서 <행 번호들> 행의 H열을 '위키반영', I열을 '<노트북명>'으로 입력해줘. 다른 셀은 절대 바꾸지 말고, 변경 전후 값을 보고해줘."
  ```
- `log.md`에 `## [YYYY.MM.DD] 위키화 | <노트북명> | 책 n권, 생성 n · 갱신 n` + 변경 페이지 목록 추가
- 사용자에게 보고: 위키화한 책, 생성·갱신 페이지, 관점 차이·사실 충돌 발견 항목, 보류 도서, 검토 요청 사항

### 사람이 마지막에 하는 일
- Obsidian에서 책 페이지·그래프 확인 → 이상 없으면 `검토완료 <노트북명>`이라고 말함 → Claude가 시트 H열을 `검토완료`로 바꿈

## 5. 신규 도서 등록 (`신규 확인`)
1. 원본 서고 폴더 폴더의 PDF 목록(로컬 경로)과 시트 D열을 대조
2. 시트에 없는 파일 목록을 대분류·세부 폴더·도서명·저자(파일명 "도서명-저자" 규칙으로 추정)로 정리해 보여줌
3. **사용자 승인 후** Aside로 시트 맨 아래에 행 추가 (연번 이어서, F열 링크는 Drive 도구로 파일 ID 조회해 기입)
4. 신규 도서는 H열을 비워 둠 (= 아직 위키화 안 함). 위키화는 사용자가 노트북에 추가한 뒤 4장으로 진행
5. `00_dashboard/대시보드.md` frontmatter의 `library_total`(서고 전체 PDF 수)과 `library_counted`(집계일)를 갱신
6. log.md에 `신규확인` 기록

## 6. 질문 (`질문: ...`)
1. `index.md` → 관련 페이지 → 근거 인용 답변 (`[[책페이지]] (장, p.쪽)`)
2. `80_journal/`에 관련 기록이 있으면 "나의 이전 기록"으로 함께 보여줌 (수정 금지)
3. 위키에 근거가 없으면 "위키에 없음"이라고 밝히고, 시트에서 관련될 만한 미위키화 도서를 추천 (다음 노트북 후보)
4. 다시 쓸 가치가 있는 답은 `50_synthesis/`에 저장할지 물어봄

## 7. 점검 (`점검`)
- 사실 충돌, 출처 없는 주장, 고아 페이지(링크 0개), 본문에 언급됐지만 링크 안 된 개념, 중복 페이지, `index.md` 누락, 시트 H열과 위키 불일치, iCloud 충돌 파일(`… (1).md` 등)
- 리포트를 먼저 보여주고 **승인받은 항목만 수정**, log.md에 `점검` 기록

## 8. 작성·표기 규칙
- 개조식(~함, ~임), 한국어 기본, 전문용어 한글(English) 병기, 날짜 YYYY.MM.DD
- 파일명: 책 `도서명-저자.md` (Drive 파일명과 동일 규칙) / 개념·인물 한글 이름 그대로 / 파일명에 `/ \ : * ? " < > |` 사용 금지
- 링크는 `[[위키링크]]`, 모든 주장 뒤에 출처 `[[책페이지]] (장, p.쪽)`, 불확실하면 `확인 필요`
- 사실 / 추정 / 적용 아이디어를 구분
- 원문 인용은 짧게(2문장 이내), 원문을 길게 옮겨 적지 않음 (저작권)
- 분야 전용 인용 체계(성경 구절, 법령 조문, 논문 인용 형식 등)는 두지 않음. 책이 다루는 1차 자료는 책 페이지·개념 페이지 안에서 일반 출처처럼 기록
- 태그 규칙 (데이터베이스 조회용, Dataview 활용)
  - `분야/<시트 B열 대분류에서 번호 뗀 이름>` (예: `분야/인문`, `분야/일반도서`) + 일반도서는 세부 폴더도 추가 (예: `분야/마케팅`)
  - `유형/<단행본·교재·주석·강연자료·보고서 등>`
  - 개념·인물 페이지의 `sources`에는 근거 책을 모두 나열 → 책 수로 중요도 파악

## 9. 안전 규칙
- 파일 삭제·이동, 시트 행 추가, 외부 발송은 사전 승인 후 실행 (단, 4장 ⑧의 H·I열 상태 기입은 위키화 절차의 일부로 승인된 것으로 봄)
- NotebookLM에서는 읽기·질문만 함. 노트북 삭제, 소스 삭제, 공유 설정 변경 금지
- 인증 정보는 파일이나 대화에 적지 않음
